# 照片上传与 AI 生成流程图（微信云开发 / Serverless 版）

> 技术映射：云存储(底层腾讯云 COS) 替代「COS Bucket」、`wx.cloud.uploadFile` 自带登录态鉴权故**省去 STS 临时凭证环节**；云函数 替代「服务端」；云数据库 替代「DB」；AI 生图耗时较长，采用**异步任务**（提交 + 轮询 / 订阅消息）。

```mermaid
flowchart TD
    %% ===== 阶段1: 端上直传云存储 =====
    A([用户在小程序选择照片]) --> A0[客户端取登录态 openid<br/>本应用强制登录, openid 已缓存]
    A0 --> B[按命名规则构造原图文件名:<br/>openid_毫秒时间戳_4位随机(数字+字母)_original.后缀]
    B --> C[wx.cloud.uploadFile 以该名直传云存储]
    C --> C1{上传成功?}
    C1 -->|失败| C2[提示上传失败, 允许重试]
    C2 --> B
    C1 -->|成功| D[拿到 fileID/链接]

    %% ===== 阶段2: 云函数提交生成任务 =====
    C --> D[调用云函数 gen: fileID + 风格 + prompt]
    D --> D1{网络请求成功?}
    D1 -->|失败| D2[提示网络异常, 允许重试]

    E1 -->|通过| F[云函数写云数据库 Task=处理中, 调 AI 提交生成, 返回 taskId]

    F -.提交后异步.-> T[定时触发器云函数 / AI 回调云函数: 查询 AI 任务状态]
    T --> S1{AI 生成成功?}
    S1 -->|失败| S2[更新 Task=失败]

    S2b --> S3[云函数取生成图, cloud.uploadFile 以该名回传云存储]
    S3 --> S4{二次上传成功?}
    S4 -->|失败| S5[Task=失败, 内部重试/告警]
    S4 -->|成功| S6[更新 Task=完成, 写入 resultFileID]
    S2 -.影响轮询.-> G1
    S5 -.影响轮询.-> G1
    S6 -.影响轮询.-> G1

    %% ===== 阶段5: 我的作品(配对查询) =====
    N --> P[我的作品: 云函数按 openid + status=完成 查询配对]
    P --> P1([端展示 original + result 配对列表])

    %% ===== 阶段6: 定时清理(只上传未生成的孤儿数据, 逻辑删除) =====
    CT[定时触发器云函数: 扫描 tasks<br/>status!=完成 且超保留期] --> CT1[置 deleted=true 逻辑删除, 保留实际文件]
    CT1 --> CT2([记录标记删除, 云存储文件不变])
```

## 流程说明（Serverless 版）

1. **端上直传云存储（成功/失败）**
   - 成功：`wx.cloud.uploadFile` 直传，拿到 `fileID`（云存储即腾讯云 COS，自带登录态鉴权，无需 STS 临时凭证）。
   - 失败：提示并允许重试上传。

2. **提交生成任务（云函数，成功/失败）**
   - 成功：云函数校验参数与 `fileID` 归属/存在性，写云数据库 `Task=处理中`，调用 AI 提交生成，立即返回 `taskId`。
   - 网络失败：提示重试；校验不通过：返回参数错误，提示重选风格/输入。

3. **端轮询 / 订阅消息**
   - 小程序轮询 `Task` 状态（或用一次性订阅消息推送"生成完成"）。处理中继续轮询；完成则 `getTempFileURL` 取结果图展示；失败可点击重试（重新调用云函数，原图已在云存储不必重传）。

4. **服务端异步生成（独立链路）**
   - 由**定时触发器云函数**或 **AI 平台 webhook 回调云函数**查询 AI 任务状态：
     - AI 失败 → `Task=失败`，通知用户重试；
     - AI 成功 → 云函数取生成图，`cloud.uploadFile` 二次上传云存储（结果图与原图分离）→ 更新 `Task=完成` 并写入 `resultFileID`。

## 文件命名规范

本应用强制用户登录，故 `wxopenid` 始终可得（端上登录态已缓存；云函数内从调用上下文 `OPENID` 获取）。

| 文件 | 命名规则 | 生成方 | 配对键 |
|---|---|---|---|
| 用户原图 | `wxopenid_毫秒时间戳_4位随机(数字+字母)_original.图片后缀` | 客户端上传前构造（`wx.cloud.uploadFile` 的 `cloudPath`） | `openid_毫秒时间戳_4位随机` |
| AI 生成图 | `wxopenid_毫秒时间戳_4位随机(数字+字母)_aigc.图片后缀` | 云函数（结果链路）**复用原图同一串** `毫秒时间戳_4位随机` 构造 | 同上（与原图一致） |

> **配对键 `pairId` = `openid_毫秒时间戳_4位随机`**：原图与 AI 图共用同一 `pairId`，因此凭 `openid_{pairId}` 即可同时定位「原图 `..._original`」与「生成图 `..._aigc`」这一对。

- **图片后缀**：原图沿用用户上传的真实后缀；AI 图按模型实际返回格式（png/jpg/webp 等）。
- **4 位随机字符**：大小写字母 + 数字，保证同一用户同毫秒内也不会撞名。
- **原图为何端上命名**：`wx.cloud.uploadFile` 的路径由端指定，故端用缓存的 `openid` 直接拼名上传；万一撞名（概率极低）云存储会覆盖，必要时可在失败分支改为重拼随机段重试。
- **AI 图为何能复用同一 pairId**：结果链路完全在服务端，云函数从 `tasks` 记录的 `originalName` 中解析出 `openid_毫秒时间戳_4位随机`，原样套用到 `_aigc` 文件名，**不再生成新的时间戳/随机串**。这样原图与生成图天然成对。
- **如何找回配对**：两种方式任选——① 查 `tasks` 中 `status=完成` 的记录，直接拿 `originalFileID` + `resultFileID`；② 扫描云存储，按 `openid_{pairId}` 前缀同时匹配 `_original` 与 `_aigc` 两个对象。

## 数据模型与查询 / 清理策略

### 云数据库 `tasks` 集合字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 任务 id |
| `openid` | string | 所属用户（强制登录可得） |
| `originalName` | string | 原图文件名（`openid_..._original.后缀`）；`pairId` = 由本字段解析出的 `openid_毫秒时间戳_4位随机`，原图与结果图共用，用于配对与存储对象互查 |
| `originalFileID` | string | 原图云存储 fileID |
| `style` | string | 用户选定风格 |
| `prompt` | string | 提示词 |
| `status` | string | `处理中` / `完成` / `失败` |
| `resultName` | string | aigc 文件名（仅完成时） |
| `resultFileID` | string | 结果图云存储 fileID（仅完成时） |
| `aiTaskId` | string | AI 平台侧任务 id（用于异步轮询/回调） |
| `createTime` | date | 创建时间 |
| `updateTime` | date | 更新时间 |
| `deleted` | boolean | 逻辑删除标记（默认 false）；清理时置 true，**实际文件保留不删** |

### 按 openid 的查询场景

- **用户上传了多少张**：`where openid == X and deleted == false` 计数（所有未逻辑删除的上传）。
- **哪些 AI 生成完成**：`where openid == X and status == '完成' and deleted == false` 计数。
- **用户只看配对数据**：前端只查 `status == '完成' and deleted == false`，返回 `{originalFileID, resultFileID}` 配对列表，批量 `getTempFileURL` 后展示原图 + AI 图配对。未完成的（处理中/失败）及已逻辑删除的均不进入作品列表。

### 清理策略（只上传未生成的数据，逻辑删除、保留文件）

采用**逻辑删除**：清理只置 `deleted = true` 标记，**不删除云存储中的实际文件**，便于追溯与恢复。分两层：

1. **库标记清理（定时触发器云函数）**：扫描 `tasks` 中 `status != '完成'` 且 `createTime` 超过保留期（建议 7 天）且 `deleted == false` 的记录 → 置 `deleted = true`。保留期内不标记，留给用户重试。
2. **纯孤儿兜底（云存储生命周期规则，可选）**：针对"上传了但从未调用 `gen`、因此无 `tasks` 记录"的对象，若将来确实需要回收存储，可配置云存储生命周期规则自动过期删除 `original_*` 前缀、超过 N 天未被引用的文件；当前方案默认**保留文件不删**，仅依赖第 1 层做逻辑标记。

> 说明：因本应用**不做查重**，上传即存；只有最终 `status=完成` 且 `deleted=false` 的配对数据长期可见，其余（处理中/失败/纯上传未生成）在保留期后仅做逻辑删除标记，实际图片仍保留在云存储。

## 部署组件清单

| 角色 | 云开发组件 |
|---|---|
| 原图/结果图存储 | 云存储（腾讯云 COS） |
| 服务端逻辑 | 云函数（`gen` 提交任务 / 触发器或回调云函数 查结果） |
| 任务状态 | 云数据库（文档集合 `tasks`） |
| 端侧调用 | `wx.cloud.uploadFile` / `wx.cloud.callFunction` / `wx.cloud.getTempFileURL` |

> 注意：云函数默认超时 3s、最大约 60s。若 AI 生图单次可在 60s 内返回，可在云函数内同步等待（最简）；若超时，必须走上述异步（提交 + 触发器/回调轮询）。长任务也可改用**云托管（CloudBase Run）**跑容器以放宽超时。
